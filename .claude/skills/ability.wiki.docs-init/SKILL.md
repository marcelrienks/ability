# Wiki Docs Init

One-time setup to discover, organize, and index all documentation in a project. Creates `wiki/` (all wiki content) and `wiki/raw/` (static assets) at the project root, consolidates scattered documentation, removes obsolete empty folders, and generates a persistent context map.

## I/O exception

Declared `io: external` (default rule is `data/` in, `<repo root>/<skill-name>/` out).

- Operates in place on the project in the current directory: moves documentation into `<project>/wiki/` and `<project>/wiki/raw/`, removes emptied folders.
- Does not use `data/` or a skill output folder. Content is preserved; only locations change.

## Workflow

### 1. Create folder structure and organize

```bash
python3 .claude/skills/ability.wiki.docs-init/scripts/organize.py
```

Optional `--project DIR` (default: current directory). The script prints an audit trail of every move; report counts to the user. What it does:

1. **Creates** `wiki/` and `wiki/raw/` at the project root.
2. **Markdown**: moves every `.md` file except the root `README.md` (which stays in place).
   - `socs/` contents are flattened into `wiki/` (name collisions fall back to a path-qualified name).
   - All other markdown keeps its folder structure under `wiki/` (e.g. `docs/guides/auth.md` → `wiki/docs/guides/auth.md`; for mixed folders only the markdown moves).
   - Markdown under `exports/` or `clipped/` goes to `wiki/raw/Exports/`.
3. **Static assets** go to `wiki/raw/<Type>/` with original filenames: `.pdf` (PDFs), `.docx/.doc` (Documents), `.xlsx/.xls` (Spreadsheets), `.pptx/.ppt` (Presentations), `.vtt/.srt`, anything named `transcript`/`captions` or under `transcripts/` (Transcripts), `.txt` (Notes), and `.tar.gz`/`.zip` under `repos/` (Repos). Build/config `.txt` files (`requirements*.txt`, `CMakeLists.txt`, `LICENSE*.txt`, `robots.txt`) are skipped.
4. **Exclusions**: dot-prefixed directories (`.github/`, `.git/`, `.cel/`), `node_modules/`, `vendor/`, `venv/`, names containing `archive`/`backup`/`bak`, external code (`addons/`, `plugins/`, `third_party/`, `external/`, `lib/`, `libs/`), generated output (`dist/`, `build/`, `out/`), the existing `wiki/`, and `specs/` only when generated by speckit (all subdirectories start with `spec-`).
5. **Clean-up**: removes folders left completely empty by the moves (e.g. `docs/`), and empty `orig/` / `archive/` folders. Folders still holding code or other files are kept.

### 2. Generate persistent context

Invoke `/ability.wiki.docs-read`. It creates `.cel/context.md` with project analysis, hashes, and a context map, preventing redundant reading later.

## Notes

- One-time operation: afterwards place new wiki content in `wiki/` or `wiki/raw/` by hand. Safe to re-run; already-organized files are not touched.
- Prerequisite for `/ability.wiki.docs-read`, `/ability.wiki.docs-simplify` and `/ability.wiki.docs-write`.
- Typical flow: `docs-init` (organize) → `docs-simplify` (consolidate) → `docs-read` (refresh context). `/ability.wiki.docs-run` runs the full chain.
